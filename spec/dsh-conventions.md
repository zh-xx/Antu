# Building the DSH plugin inside DSH's own conventions

> Status: **in force** for everything under `tools/dsh/`. Written against DeepSeek Harness **0.2.0-rc.2**. The product decision (maintainer, 2026-10): the plugin is built **inside DSH's official conventions**, not around them. Where DSH offers an extension point for something, we use it; we do not copy state into a private store, listen to the DOM ourselves, or reach into internals. The plugin's own design is in [dsh-plugin.md](dsh-plugin.md); this file is the rulebook it must obey.

## 1. What counts as "official"

In order of authority:

1. **The package READMEs** shipped with the installed DSH: `node_modules/@deepseek-ai/<package>/README.md`. They describe the public face (`ctx.<service>`), the seats (slots), and what is deliberately not offered. The ones this plugin touches: `dsh-client-ui-sidebar-right`, `dsh-client-resources`, `dsh-client-shortcuts`, `dsh-client-ui-shortcuts`, `dsh-client-ui-tool`, `dsh-client-locale`, `dsh-tools`.
2. **The official plugins that already do the same thing**, read as worked examples: `dsh-client-ui-plan` (a resource type, a provider, a tab body, a turn tail), `dsh-client-ui-deliverables` (a turn tail, a tool row), `dsh-client-ui-sidebar-documentpreview` (a resource type).
3. Nothing else. A behaviour seen only by trying it in a browser, or only in a bundle's internals, is **not** a contract: do not build on it.

**Before using a DSH API for the first time**, find it in (1) or (2) and write the file and the section in the PR. **If neither documents it, do not use it**: ask the maintainer. A deviation that cannot be avoided is written down in §4 with its reason and the issue that will remove it.

## 2. The rules

| 8   | **Declare what we depend on.**                                                                                                                                                     | Services in `inject` / `ctx.inject([...])`; the client packages that provide them in the manifest's `dsh.client.inject`, as the official plugins do (the plan plugin lists locale, resources, remotes, sidebar-right, chat, conversation).                                                                                                                                                                                                                                                                                                     | `package.json` of `dsh-client-ui-plan`, `-deliverables`, `-sidebar-documentpreview`                                                                            |

## 3. How to work

1. **Plan from the README.** The brief for a DSH worker names the README sections and the official plugin to copy the pattern from (the paths are `node_modules/@deepseek-ai/…`).
2. **Review against §2.** Every PR touching `tools/dsh/` states which rules it relies on. A reviewer rejects raw DOM listeners, private storage, and any DSH internal not in §1.
3. **Test in a real DSH** (the headless and web profiles; see `CLAUDE.md`): the feature, then a **page reload**, then closing and reopening, because most deviations hide in what survives a reload.
4. **A new DSH version re-opens this file.** Read the READMEs of the packages in §1 again before moving the supported range.
