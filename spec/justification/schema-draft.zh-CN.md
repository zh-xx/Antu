> 状态：**已实现**（状态行对照 0.8.0 检查过）。校验（§5）、排布（§6.1）、画法和界面（§6.2）都已实现，**语料是两份虚构案例，另有六份给 agent 的小示例**。标 **⚠ 提议** 的是在发起人改动之前一直有效的方案；§7 列出还没回答的问题，以及在回答之前 schema 怎么走。
> 依据：`spec/v0-architecture.zh-CN.md` 的共用约定层（引用一律用 id / 内容元素都有 label / 可选字段宽松）和它 §3 的差异分类（元素结构装不进现有类型，才注册新的顶层类型）。写法参照 `spec/relationship/schema-draft.zh-CN.md`。
> 范围：证成图 = **一方对"为什么这样裁判"的说理**：规范加事实，怎样一层一层推出结论。已发生的事按时间叙述 → `fact`；谁与谁什么关系 → `relationship`；程序的路径 → `procedure`。

## 0. 决定

发起人已定（2026-09）：

1. **节点分三种：事实、推断、评价。** 三种被质疑的方式不同：事实问证据，推断问逻辑，评价问价值判断。图上必须分得开。
2. **事实节点在证成图里自己写**，自带文字、时间和出处，**不引用**事实图里的事件 id。代价是同一件事在两张图里各写一遍，好处是证成图可以单独使用。
3. **一张图画一方的说理。** 先只做这个，比如只画法院的裁判理由。控辩双方各一棵树、由法官取舍，放在以后。

我提议的（**⚠ 提议**，见 §7）：

4. **节点叫 `nodes`，关系叫 `links`**，有 `from` / `to`。方向是**从支持的一方指向被支持的一方**：事实指向要件，要件指向结论。
5. **节点六种 `kind`**：`conclusion`（结论）、`norm`（规范）、`element`（要件）、`fact`（事实）、`inference`（推断）、`judgement`（评价）。
6. **判断点带 `holds`**：`yes` / `no`。要件、推断、评价、结论可以成立，也可以被否定（例如"特殊防卫"这一争点的结论是"否"）。
7. **连线有立场 `stance`**：`for`（支持）、`against`（反对）、`basis`（规范依据）。量刑里"严重过错"从轻、"损害远大于所保护的权益"不从轻，要能同时画出来。
8. **`groups`** 用来框出"争点"（一个争点一个框），和事实图的 `groups`、程序图的 `stages`、关系图的 `groups` 是同一个思路。
9. **`sources` 原样复用**（`spec/source-schema-draft.zh-CN.md`）：规范用 `statute`、判例用 `case`，事实的出处用 `case` / `evidence` 等。
10. **没有 `views`。**

## 1. 信封

```jsonc
{
  "specVersion": 1,
  "type": "justification",
  "title": "方远案（虚构） · 防卫过当的说理",
  "speaker": "示例省高级人民法院（二审，虚构）"   // 可选：这是谁的说理
}
```

`speaker` 是这一棵树的出处，显示在标签卡上。一张图只有一个 `speaker`（决定 3）。

## 3. 字段规则

### 图级字段

| 字段 | 必填 | 类型 | 说明 |
|---|---|---|---|
| `speaker` | ❌ | string | 这一棵树是谁的说理，写在信封里 |
| `groups` | ❌ | object[] | `{ id, label }`，一个争点一个 |
| `nodes` | ✅ | object[] | 节点，见下 |
| `links` | ✅ | object[] | 节点之间的连线，见下 |
| `sources` | ❌ | object[] | 图内的来源表；七类与定位字段完全复用 |

### `nodes[]` 的每一项

| 字段 | 必填 | 类型 | 说明 |
|---|---|---|---|
| `id` | ✅ | string | 图内唯一，被 `links` 引用 |
| `kind` | ✅ | string 枚举 | 六种，见 §4.1 |
| `label` | ✅ | string | 节点上显示的一句话 |
| `detail` | ❌ | string | 放不进节点的全文（法条原文、判决书原句）；在浮层里 |
| `holds` | ❌ | `yes` / `no` | 这个断言在该说理里是否成立；**只用于** `conclusion`、`element`、`inference`、`judgement` |
| `combine` | ❌ | `all` / `any` | 它依据的东西怎么合起来：`all` = 须全部具备（"且"），`any` = 具备其一即可（"或"）；**只用于** `conclusion`、`element`、`inference`、`judgement`；省略 = 没有明说，见 §4.6 |
| `date` | ❌ | ISO 日期或日期时间 | **仅 `fact`**：事实发生的时间（`2032-04-14` 或 `2032-04-14T22:22`） |
| `groupId` | ❌ | string | 引用 `groups` 里的 id |
| `sourceIds` | ❌ | string[] | 引用本图 `sources` 里的 id |

### `links[]` 的每一项

| 字段 | 必填 | 类型 | 说明 |
|---|---|---|---|
| `from` | ✅ | string | 支持的一方（或规范）的 id；**连线从这里出发** |
| `to` | ✅ | string | 被支持的一方的 id |
| `stance` | ❌ | `for` / `against` / `basis` | 默认 `for`，见 §4.3 |
| `label` | ❌ | string | 线上的一句短话（如"限制从轻幅度"）；省略则不显示 |

## 4. 机制

### 4.1 节点六种  **⚠ 提议**

| `kind` | 是什么 | 在说理里的位置 | 能被怎样质疑 | 专属字段 |
|---|---|---|---|---|
| `conclusion` | 一个结论：整张图的终点，或一个争点的小结 | 最上面 | 前提不成立，或推不出来 | `holds` |
| `norm` | 规范：法条、司法解释、判例 | 叶子，只指向要件或结论 | 是否适用、怎么解释 | `sourceIds`（指向 `statute` / `case`） |
| `element` | 要件：规范拆出的一个构成要件 | 规范和事实之间 | 是否满足 | `holds` |
| `fact` | 事实：法院认定发生了的事 | 叶子，最下面 | 有没有证据 | `date`、`sourceIds` |
| `inference` | 推断：由事实推出来的断言（"警灯可见，应当知道民警未离开"） | 事实和评价之间 | 推理是否成立 | `holds` |
| `judgement` | 评价：法官对一堆事实下的价值判断（"侵害并不紧迫"） | 靠近结论 | 价值判断是否合理 | `holds` |

**事实和推断的界限**：判决书"基本案情"里陈述的、有时间和动作的，是事实；"裁判理由"里为了得出结论而由事实推出来的断言，是推断。拿不准时，问一句："这句话是在说发生了什么，还是在说因此可以认为什么？"

### 4.2 `holds`：成立，还是被否定

一个断言在这套说理里被采纳了，写 `yes`；被明确否定了，写 `no`。

被否定的一方也要画出来。最典型的是**特殊防卫**：法院说"不属于特殊防卫"。画法是：
- 结论 `"属于特殊防卫，不负刑事责任"`，`holds: "no"`；
- 要件 `"正在进行严重危及人身安全的暴力犯罪"`，`holds: "no"`；
- 一条评价 `"这些侵害是非法限制自由、侮辱、轻微殴打"` 以 `against` 指向这个要件。

这个 `no` 的结论再以 `against` 指向最终结论（"如果成立本来会推翻它，但没有成立"）。

`holds` 省略，表示这份说理没有明说成立与否。

### 4.3 连线的立场（`stance`）  **⚠ 提议**

| `stance` | 含义 | 常见的 `from → to` |
|---|---|---|
| `for`（默认） | `from` 支持 `to` | 事实 → 要件、事实 → 推断、推断 → 评价、要件 → 结论 |
| `against` | `from` 反对 `to` | 评价 → 要件（说它不满足）、被否定的结论 → 最终结论 |
| `basis` | `from` 是 `to` 的规范依据 | 规范 → 要件、规范 → 结论 |

`basis` 只能从 `norm` 出发。

**同一个结论上可以同时有 `for` 和 `against`**，这是量刑那一类争点的常态：
"如实供述"和"被害方严重过错"是 `for`（从轻），"损害远大于所保护的权益"是 `against`（限制从轻的幅度）。

### 4.6 `combine`：且，还是或

一个节点依据好几样东西时，读者最想问的是"缺一个行不行"。正当防卫的五项条件必须**同时**具备；有些规范是"具备其一即可"。

- `combine: "all"`：它依据的（`for` 连线来的那些）须全部具备。缺一个，它就不成立。
- `combine: "any"`：具备任何一个就够了。
- 省略：说理没有明说，读者按规范自己理解（原来的读法）。

只管 `for` 的连线。`against`（反对）和 `basis`（规范依据）不参与：规范依据本来就是这个节点的前提，反对是另一回事。

图上，节点第一行小字里带一个小标记：`且` 或 `或`（英文 `all of` / `any of`），指到节点上悬停时浮层里也写全（"它依据的须全部具备"）。只是画法，不改变几何。

同一个节点上 `combine` 和 `holds` 要对得上，校验会提醒（规则 20、21）。

### 4.4 争点（`groups`）

判决书的说理通常按争点组织（"是否具有防卫性"、"是否特殊防卫"、"是否过当"）。一个争点是一个分组，一个节点最多在一个分组里。

**规范要放在它所解决的争点里**。同一条规范用在两个争点里（第 20 条第 2 款既管"过当"，又管"减轻处罚"），就写成两个 `norm` 节点，各放各的分组，指向同一个 `sourceIds`。

### 4.5 来源（`sources`）与"没有视角"

`sources` 原样用共用的七类。这里用到：

- 法条：`statute`，`loc` 写 `lawName`、`article`、`version`；款项写在节点的 `label` 里（"第 20 条第 2 款"）。
- 裁判文书：`case`。**同一份文书的不同部分可以是两条来源**（"基本案情"和"裁判理由"），这样事实和推断各自指向对的一段，不需要新字段。
- 证据：`evidence`（见 §7 第 2 条）。

没有 `views`，理由同关系图：视角是事实图的概念。

## 5. 校验规则  **⚠ 提议**

只是草案，没有代码。错误逐条报，带字段路径和 id。

| # | 规则 | 结果 |
|---|---|---|
| 1 | `nodes` 和 `links` 是非空数组 | 报错 |
| 2 | `id` 必填，且在 `nodes` 内唯一 | 报错 |
| 3 | `node.kind` 在六种枚举内；每个节点有非空 `label` | 报错 |
| 4 | `from`、`to` 指向存在的节点；不许 `from === to` | 报错 |
| 5 | `stance` 在 `for` / `against` / `basis` 内；`basis` 只能从 `norm` 出发 | 报错 |
| 6 | 不许重复的连线（`from`、`to`、`stance` 都相同） | 报错 |
| 7 | `groupId`、`sourceIds` 指向存在的 id | 报错 |
| 8 | `holds` 只能是 `yes` / `no`，且不出现在 `fact`、`norm` 上 | 报错 |
| 9 | `date` 只出现在 `fact` 上，且是 ISO 日期或日期时间 | 报错 |
| 10 | 连线不成环 | 报错 |
| 11 | `fact` 和 `norm` 没有入线（它们是叶子；证据层见 §7 第 2 条） | 报错 |
| 12 | 至少有一个 `conclusion` 没有出线（整张图的终点） | 报错 |
| 13 | 有不止一个终点结论 | **提示**（画的是一棵树吗？） |
| 14 | 除终点结论外，节点没有出线（它不支持任何东西） | **提示** |
| 15 | `fact` 没有 `sourceIds` | **提示**（哪里认定的？） |
| 16 | `norm` 没有 `sourceIds` | **提示**（依据哪一条？） |
| 17 | 一个 `holds: "yes"` 的要件，它的 `for` 连线全部来自 `holds: "no"` 的节点 | **提示**（前提被否定，结论却成立） |
| 18 | 一个结论或要件的入线里没有任何 `for` 或 `basis`（`holds: "no"` 的除外：被否定的节点不需要支持） | **提示**（没有支持它的东西） |
| 19 | `combine` 是 `all` / `any`，且只在能被支持的四种节点上（报错）；不足两条 `for` 连线的节点写了 `combine`（提示：没有什么可合的） | 报错 / **提示** |
| 20 | `combine: "all"` 而 `holds: "yes"`，可它依据的某个节点被否定了 | **提示**（须全部具备，却有一个被否定） |
| 21 | `combine: "any"` 而 `holds: "no"`，可它依据的某个节点成立 | **提示**（具备其一即可，却有一个成立） |

结构错误会挡住绘制，提示不会。与关系图、程序图同一个分法。

## 6. 呈现  **⚠ 提议**

### 6.1 排布（已实现）

`src/renderers/justification/tree/layout.js`，纯几何，不依赖浏览器。

- **一棵从结论往下的树。** 连线是从支持的一方指向被支持的一方，所以交给 ELK 时每条线反过来，结论就在最上（横向时在最左）。
- **一条事实（或规范）在数据里是一个节点，画的时候在每个用到它的争点里各画一份。** 事实和规范是叶子，可以同时支持几个争点里的东西（辱骂这条事实既支持"防卫性"，也支持"被害方过错"）。它只在数据里写一遍，图上在每个用到它的争点框里各出现一次，副本的标签写"同上"。这样每个争点的框里装着它需要的全部东西，没有线要跨过整张图去找另一个框里的事实。只被一个争点用到的，就站在那个争点里，不管它自己的 `groupId` 写的是哪个。
- **同一个争点里，被几个节点用到的事实，在每个用到它的节点旁边各画一份**（支持三个或更多要件的规范也一样）。只画一份的话，通向几个节点的线要跨过中间的层，撞上站在那里的东西；每处用到都画一份，事实就成了树，线不交叉。底部有"合并重复"开关，可以改成各画一份（节点少，线长，交叉多）；这是读者的选择，按图记在浏览器里，数据不变。两个示例案例上的效果：线和线的交叉，楼道案、方远案（横向）从 11 和 6 降到 0 和 0，代价是比合并的图多画 5 个和 4 个节点（方远案：拆开画 49 个，合并 45 个）。
- **每个争点排几种样子，留交叉最少的**：ELK 用几个种子、两种分层办法各排一遍，规范放在要件上面或放在事实一侧各试；每一类里最好的再真的走一遍线，留真实交叉最少的。种子是固定的，同样的数据永远排出同样的图（ELK 的 0 号种子按时间取随机数，所以不用它）。
- **规范站在要件的上一层**，和争点结论同一层，线从规范往下指向各个要件。这样规范离要件很近，不必绕到事实那一层去。
- **一个争点一个框，框内单独排。** 每个争点由 ELK 分层单独排，只看争点内部的连线，框和内容一样大（ELK 排不了"框住了跨层的节点"，关系图的阵营也是这个原因）。不属于任何争点的节点（终点结论）自成一组，摆在所有争点之上，居中。
- **争点并排，顶端对齐**（竖向时左右并排；横向时上下叠放）。
- **连线用同一个正交寻路**（`procedure/flow/router.js`）：折数最少、其次最短，避开每个节点和争点标题。同一种立场进同一个节点的连线共用主干（五条事实进同一个要件，读成一束）。争点内的连线先只在该争点的框里找路，跨争点的先只在两端周围的矩形里找路，找不到再放开，否则整张图一起找要好几秒。
- **只有写了 `label` 的连线才有标签**，放在它自己那条线上。
- **保持书写顺序。** 同一个父节点下的节点，先写的先排（ELK 的 `forceNodeModelOrder`）。
- **横向是竖向那张图的转置**，一份代码，两种方向。**默认横向**：结论在左，事实在右，像一句话从左读到右；竖向时同一争点的事实排成一长行，太宽。
- `holds` 和 `stance` 只是画法，不改变几何。

已知不足：各争点的结论连到终点结论的线很长（争点并排时不可避免）；示例（40 个节点、48 条线，其中 5 条事实各画了两份）排一次约 1 秒，最近几次的排布结果按内容缓存。

### 6.2 画法（已实现）

`src/renderers/justification/tree/`：`JustificationNode.jsx`、`LinkLayerNode.jsx`、`JustificationRenderer.jsx`、`JustificationDock.jsx`。争点框用关系图的分组框。

- **六种节点，六种样子**（颜色来自主题，见 `spec/theme.md`，作为 SVG 属性挂上，导出的图片带得走；各主题里的画法相同，所以黑白下也分得开）：结论是粗框；规范是灰底的直角框；要件是圆角药丸；事实是细线平框；推断是点线框；评价是粗线灰底框。节点的第一行小字写出是什么（"事实"、"要件"……），事实在这一行带时间，`holds` 写成"✓ 成立"或"✗ 否定"，副本写"同上"。
- **被否定的节点**（`holds: "no"`）淡化、虚线框、文字划去，黑白打印也看得出来。
- **连线的立场**：支持是普通的线；反对是虚线（法律蓝主题下为红色）；规范依据是点线。每种立场一个箭头。
- **指向一个节点，点亮它的整条链**：它依据的一切（向下到事实和规范）和它指向的一切（向上到终点结论）留下，其余淡出。同一条事实的几份副本一起点亮，各带着往上的那条链。这是读一份说理时对一个节点的自然问题："它凭什么，又通向哪里"。
- 悬停看一眼，点击钉住：浮层里是全文（`detail`）、它依据什么、它指向什么、来源。
- **控制条**：标签开关（只有当有连线写了 `label` 才出现）、横向/竖向（横向在前，也是默认）、曲线/折线、语言、导出图片。没有"按节点种类筛选"的开关：读说理的人是顺着链读，不是按种类筛。
- **收起争点**：读者的选择，不是数据里的东西。每个争点框的标题是个按钮（前面一个小箭头）：点一下，这个争点收起来，只留下它的结论（没有结论的争点，留下直接连到终点结论的那个要件）；框变成虚线的小框，标题后面写"已收起 N 个"。事实和规范、争点里其他的节点，和碰到它们的连线，都不画。再点一下展开。控制条上有"收起争点"：全部收起，或全部展开。收起会重新排布并重新适应视图（几何变了），并按图记在浏览器里。一条事实如果另一个争点还在用，它在那个争点里的那一份不受影响。收起后的节点的浮层里，依据仍然写全。全部收起时，方远案只剩 6 个节点，一屏放得下。
- 点亮、淡出、标签开关都只是画法，不改变几何，视图不会被抛回总览（issue #21）。

## 7. 还没回答的问题，以及暂时怎么走

1. **要件之间是"且"，还是"或"？（已回答，见 §4.6）** 节点上有可选的 `combine: "all" | "any"`；省略就是没有明说。
2. **证据层。** 事实是由什么证据认定的？ 判决书的裁判理由往往不写，要看一审判决书或卷宗。 **暂时：** `fact` 是叶子，只有 `sourceIds`；证据层留作以后（`evidence` 类来源已经可以引用）。
3. **两方对立。** 控辩双方各一棵树，法官在争点上选择一方。 **暂时：** 只做一方的说理，见决定 3。
4. **可推翻性。** 法律规范常有例外和抗辩，结论在有反驳时可能被推翻（图尔敏模型里的"反驳"和"限定"）。 **暂时：** 用 `against` 和被否定的 `holds: "no"` 节点表达最常见的一种，不做更多。
5. **节点六种是否太多？** 可合并的候选：`element` 并进 `judgement`，或 `inference` 并进 `judgement`。 **暂时：** 六种，因为决定 1 要求事实、推断、评价分开。
6. **`holds` 是否需要"待定"？** 有些争点法院没有下结论。 **暂时：** 省略就是"没有明说"。
7. **第一批语料。** 我提议先用方远案（有明确的规范要件和事实认定）；之后可以加虚构网络商城案、楼道充电劝阻案（虚构）。 **暂时：** 方远案一份。

## 9. 与另外几类的比较

| | 事实图 | 程序图 | 关系图 | 证成图 |
|---|---|---|---|---|
| 结构 | 车道上的时间点和事件 | 节点和边的自由图 | 当事方和关系的自由图 | 自上而下的支持树 |
| 时间 | 轴 | 流程 | 一个 `asOf` 日期 | 只有事实节点带日期 |
| 分组 | `groups`（分侧） | `stages`（分栏） | `groups`（分框） | `groups`（争点） |
| 边的意思 | 无 | 流转（可带条件） | 关系的种类 | 支持 / 反对 / 依据 |
| 专属字段 | 日期 | `condition`、`main` | `share`、`amount`、`secures` | `holds`、`stance` |
