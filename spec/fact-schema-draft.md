# fact（事实图）· Schema 草案 v0

> 状态：**草案，待项目发起人审定**。字段名/约束均可改。
> 依据：`v0-architecture.md` 中的公共约定层（id 引用 / 都带 label / 可选宽松）。
> 范围：fact = 已发生**实体事实**的时间叙事。程序事件（立案/开庭/判决）不属此类 → procedure。

## 1. 信封层（与所有类型共享）

```jsonc
{
  "specVersion": 1,
  "type": "fact",
  "title": "华远贸易诉鑫城建材案 · 事实经过"
}
```

## 2. 内容层草案

```jsonc
{
  "type": "fact",
  "title": "华远贸易诉鑫城建材案 · 事实经过",

  // 图内自带的来源表（方案 B：只含本图引用到的来源）
  // source.type：evidence/document/contract/statute/case/… —— 见 source-schema-draft
  "sources": [
    { "id": "s-1", "type": "contract", "name": "借款合同", "loc": { "file": "借款合同.pdf", "page": 3 } },
    { "id": "s-2", "type": "evidence", "name": "银行转账流水", "loc": { "file": "流水.pdf", "page": 1 } }
  ],

  // 按时间排序的事件（核心内容）
  "events": [
    { "id": "ev-1", "date": "2023-03-10", "label": "签订借款合同",
      "kind": "签约", "actor": "华远贸易 / 鑫城建材",
      "detail": "借款 500 万元，期限 12 个月", "sourceIds": ["s-1"] },

    { "id": "ev-2", "date": "2023-03-12", "label": "款项交付",
      "kind": "履行", "actor": "华远贸易", "detail": "转账 500 万元至被告账户",
      "sourceIds": ["s-2"] },

    { "id": "ev-3", "date": "2023-06-01", "dateEnd": "2023-12-31", "label": "分期还款期",
      "kind": "履行", "actor": "鑫城建材", "detail": "约定分 6 期偿还，前 3 期正常" },

    { "id": "ev-4", "date": "2024-01-15", "label": "停止还款",
      "kind": "违约", "actor": "鑫城建材", "detail": "第 4 期起未付",
      "sourceIds": ["s-1"] }          // ← 同一来源被多个事件引用（图内多对多、零冗余）
  ]
}
```

> **多对多说明**：来源在**图内 sources 表**里存一份，事件用 `sourceIds` 引用——一个事件可挂多个来源，一个来源可被多个事件引用。零冗余的关键是"引用而非复制"，见主文档第 4 节。

## 3. 字段规则（草案）

### events[] 每项
| 字段 | 必填 | 类型 | 说明 |
|---|---|---|---|
| `id` | ✅ | string | 全图唯一，供引用 |
| `date` | ✅ | string (YYYY-MM-DD) | 排序键；数组应按 date 升序 |
| `label` | ✅ | string | 图上显示的一句话标题 |
| `kind` | ✅ | 枚举 | 事件类别，见下 |
| `actor` | ❌ | string | 谁做的（可多人）；**草案先做字符串，是否升格为引用待议** |
| `detail` | ❌ | string | 详情，点击展开 |
| `dateEnd` | ❌ | string | 事件是"持续期间"时给结束日（如分期履行期）→ 图上画时段条 |
| `sourceIds` | ❌ | string[] | 引用本图 `sources` 里的 id（多对多，见上） |

### sources 说明（方案 B：图内自带）
- 每张图 JSON 自带 `sources` 数组，仅含**本图引用到**的来源（单图自洽、可独立渲染、便于分享）；
- 事件用 `sourceIds` 引用图内 sources；
- 校验层检查：`sourceIds` 里的每个 id 必须存在于本图 `sources`（悬空引用报错）；
- 将来路径（方案 C 全局表）不预先设计，见 source-schema-draft §0。

## 4. kind 枚举（草案，待扩充/调整）

签约 · 履行 · 违约 · 催告 · 侵权 · 登记 · 送达 · 其他

> 受控枚举原则：新增业务场景 = 给枚举加值（版本化），不改结构。

## 5. 呈现（渲染器将来按此工作，草案）

- 默认：单线纵向时间轴，事件按 date 排列；持续事件画成时段条；
- 参数 `layout: "lanes"`（可选，将来）→ 按 actor 分行，本版不做。
