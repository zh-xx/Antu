# fact 渲染思路 v0

> 状态：**核心思路已确认**（2026-09）。
> 配套：数据怎么摆见 `fact-timeline-rules.md`；本文讲的是**怎么画、怎么交互、代码怎么分**。
> 用法：§1 到 §4 是核心思路，要改得重新讨论；§5 的尺寸配色是初版参数，随时可调。

---

## 0. 一句话

把一份 fact 规范画成一张**固定网格**：行是时间，列是车道，一格一个事件。

## 1. 引擎与渲染器的分工（通用，不限于 fact）

- **渲染器只做一件事**：把规范翻译成 `{ nodes, edges }`。
- **画布由引擎统一提供**：缩放、平移、小地图、节点点击这些公共能力只写一次，每个渲染器不重复实现。
- **布局算法各渲染器自负**：fact 用本文的网格算法；将来的关系图、程序图、证成图用 dagre 或自算。
- 收益：新增一种图 = 注册一个新渲染器，画布那块一个字不用改。

## 2. 校验与渲染共用同一份排布计算

- 排布规则**只有一份实现**：`src/core/factGrid.js`。
- 校验层拿它报错，渲染层拿它算坐标，两边永不脱节。
- 这是一条硬约束：不允许在校验层和渲染层各写一套规则。

## 3. 网格模型

| | 由什么决定 |
|---|---|
| **行** | 时间槽（`slots` 数组下标，自上而下就是时间先后） |
| **列** | 站位 × 主体：第 1 侧各主体 · 轴线 · 第 2 侧各主体 |
| **格** | 最多一个事件 |

- **空格子保留位置**，什么都不画。空位本身是信息（这一方在这类事上没有动作）。
- **卡片 = 格子减去四周边距**，所以所有卡片一样大，天然对齐。
- 站位与距离的完整规则见 `fact-timeline-rules.md`。

## 4. 画面元素与交互

- **轴线**：中间那一列的竖线，底端一个向下箭头表示时间方向；每个槽在轴线上打一个轴点。
- **引线**：卡片靠轴的一侧拉一条细线，连到本槽的轴点。卡片本来就在轴线列时，不画引线。
- **轴上不写时间**，时间印在每张卡片上。
- **列标题**：一行写“第 N 侧 · 组名（图例文字）”；只有该侧有多列（多主体）时，才在下面补一行主体名。
- **卡片只放四样**：时间、标题、主体标签、来源数（外加“约”标记）。`detail` 不上卡片。
- **详情**：就在卡片旁边，分两级。悬停露出 `detail` 摘要（3 行）；点击**就地钉住**，展开全文、时间说明（`dateNote`）与全部依据（名称、类型、原文摘录），可滚动。见下方 §4.1。
- **格子层**：把底层那套矩形用虚线画出来，一眼看清“整张图是矩形拼出来的”。信息栏里有开关，**默认关闭**。两侧各多画一列空位，用来显示坐标系的余量。
- **配色**：按站位配色，第 1 侧、第 2 侧、轴线各一色；卡片左侧色条与信息栏图例一一对应。
- **信息栏在左，不在上**：这张图竖着长，垂直空间稀缺、横向富余。标题、统计、图例一律放左侧栏，画布顶部**零占用**（改前两条横栏吃掉 15% 的窗口高度）。窄屏（≤1080px）自动折回顶部横条并**默认收起**。

### 4.1 详情为什么用卡片旁的浮层，而不是侧边抽屉

**任何会改变画布尺寸的面板都会让内容位移。** 侧边抽屉会把画布挤窄，点开的那张卡片跟着挪走，正好躲开你的鼠标。所以详情一律用**覆盖式浮层**：

- 画布尺寸从头到尾不变，卡片一动不动；
- 浮层宽 320px，与卡片同宽同列对齐，因此**横向永远不会溢出**；第一行的卡片浮层往下冒，其余往上冒，避开顶部；
- 触摸设备没有悬停，所以**点击必须能独立打开**（钉住态），不能只靠 hover；
- 关掉的方式有三个：点空白处、点浮层右上角 ×、直接点另一张卡。

## 6. 技术选型

**React Flow（`@xyflow/react` 12）作为四类图共用的画布。**

- fact 这一版**只用到画布级能力**：缩放、平移、自适应视图、小地图、节点点击。
- **没有用到图结构级能力**：`edges` 为空数组，不用连接点 `Handle`，本轮关闭节点拖拽。
- **保留它的理由**：四类图里三类（关系图、程序图、证成图）都是标准的节点-边图，正是它的主场；四类共用一套画布，避免每类图各造一套缩放平移；将来两处会用到更多能力，见 §7。
- **选它的代价**：约 120 KB（gzip）。当前这张图自己写缩放平移也做得到，但会破坏画布统一。

## 7. 本轮未做

| 项 | 说明 |
|---|---|
| `dateEnd` 时段条 | 一个持续事件画成跨越多个槽的竖条，正好可以用 React Flow 的边能力 |
| 拖拽编辑 | 结构上已为它留好路（顺序靠数组、同槽靠嵌套）；React Flow 自带吸附网格，与这套格子天然匹配 |
| 横竖切换 | 先做竖轴；方向留作渲染参数，逻辑不随方向变 |
| 三个以上主体的实际验证 | 规则已定，但还没铺数据验证 |
